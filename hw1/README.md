# ДЗ 1

Аналитическая модель FLOPs, памяти, задержки и энергии для CNN из задания.

Железо и софт: Tesla T4 (Colab), драйвер 580.82.07, CUDA 12.8, cuDNN 9.19, PyTorch 2.11, Python 3.13.

Запуск: в Colab открыть `hw1_colab.ipynb` на T4 и Run all (около 10 минут). Локально: `python measure.py`, потом `python calibrate.py`.

Файлы: `models.py` сеть, `equations.py` формулы, `measure.py` замеры, `calibrate.py` подбор параметров, `plots.py` графики, `results/` замеры, параметры и графики, `hw1_handwritten.pdf` вывод формул.

## Формулы

- FLOPs = B·(17712·S² + 313344)
- Bytes = 364·B·S² + 8592·B + 4161296
- Memory = 4161296 + 52·B·S²
- Latency = t0 + max_k (k·τ + Σ_{j≥k} max(M_j/β, F_j/π)), по 17 операциям
- Energy = P_s·Latency + e_F·FLOPs + e_M·Bytes

Параметры подбирал по 63 точкам основной сетки, остальные 69 точек для проверки.
Получилось: t0 = 244 мкс, τ = 20 мкс, β = 234 ГБ/с, π = 3,09 TFLOP/s, P_s = 60 Вт, e_F = 0,72 пДж/FLOP, e_M = 0.

## Результаты

Ошибка на проверочных точках: FLOPs 0%, память 53%, задержка 23%, энергия 24%.
OOM на сетке не было, формула его тоже не предсказывает. Граница OOM при S = 512: по формуле 1135, на деле 865.

## Обсуждение

- До B·S² ≈ 5·10⁴ задержка почти постоянная, 0,5–0,75 мс: GPU ждёт, пока Python запустит операции. Дальше время растёт как B·S², свёртки упираются в вычисления, relu/pool/GAP в память (около 240 ГБ/с).
- При B > 64 conv1 работает примерно в 4 раза медленнее (cuDNN меняет алгоритм), и формула занижает время в 1,2–2,2 раза. Это главная ошибка.
- T4 почти всё время работает у лимита 70 Вт, частота падает с 1590 до ~600 МГц, а π в формуле постоянная. Поэтому на средних входах формула завышает время на 10–25%.
- Энергия примерно равна мощности × время, поэтому P_s забирает почти всё. e_M = 0, потому что байты у этой сети пропорциональны FLOPs и их не разделить. Ошибки энергии повторяют ошибки задержки.
- Память: формула учитывает только веса и активации. Не учтены служебные буферы PyTorch (~10 МБ), данные MaxPool о положении максимумов (16 байт на B·S²) и рабочий буфер cuDNN, поэтому формула занижает память примерно вдвое.
